# CLAUDE.md — Marshal Project

## Правила (ОБОВ'ЯЗКОВІ)

### Issue-first rule
**Будь-яка знайдена проблема, баг, code smell, ідея для розвитку, architectural observation, security issue або TODO — ОДРАЗУ фіксується як GitHub issue.** Не тримати в голові, не залишати в коментарях коду, не відкладати на "потім".

- Репозиторій: `reznichenkoandrey/marshal`
- Команда: `gh issue create --title "..." --body "..." --label "..."`
- Якщо знайдено під час ревью/імплементації — створити issue **перш ніж** писати фікс
- У тілі issue вказувати: `file_path:line_number`, опис проблеми, пропоноване рішення
- Багато дрібних issues > один великий — легше трекати прогрес

### Labels у проєкті
- Priority: `priority:critical`, `priority:high`, `priority:medium`, `priority:low`
- Area: `area:translator`, `area:dictation`, `area:desktop`, `area:agent`, `area:bridge`, `area:chrome-extension`
- Type: `type:security`, `type:bug`, `type:feature`, `type:refactor`, `type:tech-debt`, `type:epic`

### Commit → PR → issue linking
- Кожен комміт, що закриває issue: `fix: ... (#NN)` або `feat: ... (#NN)`
- У PR description: `Closes #NN` для автозакриття

### Tests
- Runner: **vitest** (`npm test`, `npm run test:watch`)
- E2E у реальному Electron — окремо від vitest: `npm run test:e2e` (smoke),
  `npm run test:e2e:capture` (редактор захоплення), `npm run test:e2e:region`
  (геометрія виділення області), `npm run test:e2e:history` (вікно історії знімків),
  `npm run test:e2e:meetings` (вікно записів дзвінків: «Finish» для перерваних,
  «Transcribe & summarize» і нотатки),
  `npm run test:e2e:alternatives`
  (перекладач: клік по слову → альтернативи), `npm run test:e2e:captions` (живий рядок
  субтитрів), `npm run test:e2e:home` (вікно асистента: кожен стан, dock, тема, пауза
  прихованого вікна, reduced motion, вигляд Settings: rail, перемикач, Save;
  `MARSHAL_E2E_SHOTS=<тека>` — скріни кожного стану і Settings на трьох ширинах),
  `npm run test:e2e:ambient` (рамка-світіння, індикатор диктовки, міні-віджет: картки, клік /
  подвійний клік / драг, пауза після 30 с idle)
  У CI (macOS) крутяться smoke, alternatives, captions, history, meetings, home і ambient: вони працюють через
  stub-preload і не потребують TCC. `capture` і `region` — лише локально, бо їм потрібен
  Screen Recording, якого GitHub runner дати не може. Чіпаєш захоплення — запусти їх руками.
- Тести живуть у `tests/` на рівні проєкту
- Нові pure helpers мають бути `export`-нуті з testable форми (не внутрішні методи)
- Перед коммітом: `npm run check` (typecheck + test)

### First-run setup
- **macOS codesign cert (ОБОВ'ЯЗКОВО для dev):**
  1. `npm run setup:codesign-cert` — створює self-signed `Marshal Self-Signed` cert у keychain. Двічі попросить `sudo` (`security remove-trusted-cert` + `security add-trusted-cert`) — це нормально, скрипт надрукує точні команди.
  2. Перевірка: `security find-identity -v -p codesigning | grep "Marshal Self-Signed"` — має бути хоча б один рядок без "Invalid Key Usage".
  3. Чому це потрібно: без stable cert `npm run build` підписує bundle ad-hoc → новий CDHash щоразу → macOS TCC вважає це новим app → знову запитує Microphone/Screen Recording/Accessibility. Зі stable cert + фіксованим bundle ID `com.marshal.desktop.dev` grants зберігаються назавжди (див. #84).
  4. Якщо TCC після переходу на stable cert все одно показує `com.github.Electron` зі старими grants: `tccutil reset All com.github.Electron && tccutil reset All com.marshal.desktop.dev`, після цього один раз `Allow` — і тиша.
- Voice dictation:
  1. `npm run setup:dictation` — збирає `whisper-cli` у `.whisper/` і кладе модель
     (`ggml-large-v3-turbo-q8_0`, 874 МБ) у `~/Library/Application Support/Marshal/models/`.
     **q8_0 — дефолт з #282:** на записах дзвінків транскрипти ті самі, що в повної turbo
     (розбіжності — сегментація й пунктуація), resident 1.0 ГБ проти 1.85 ГБ, холодний load
     0.29 с проти 1.15 с, encode однаковий. q5_0 (574 МБ) повільніший на encode і частіше
     розходиться — не брати. Пріоритет у `WHISPER_MODELS`: q8_0 → turbo → large-v3 → small;
     у кого стоїть повна turbo, tray пропонує завантажити q8_0, стару модель не видаляє.
     **Модель НЕ в репо і НЕ в бандлі** (див. #151): вона робила DMG 1.5 ГБ при застосунку
     під 100 МБ. Одна копія на всі білди, переживає перевстановлення; override —
     `MARSHAL_MODELS_DIR`. У packaged білді ставиться з tray → «Download Dictation Model…».
     `WHISPER_MODEL=ggml-small` — 465 МБ замість 874 МБ, гірше на коротких фразах.
     **Модель тримається в пам'яті — `whisper-server` (#218).** `whisper-cli` на кожну фразу
     заново вантажить 1.5 ГБ і ініціалізує Metal: на M3 Pro це 1.6 с, **незалежно від
     довжини** (3 с і 9 с однаково). Один `whisper-server` на весь застосунок відповідає за
     ~0.6–0.7 с, а одночасні запити ставить у чергу замість того, щоб вантажити дві копії
     моделі (так фінал субтитрів сповзав до 4.7–11.3 с, #219). Стартує при першій потребі,
     гаситься після 10 хв простою (`desktop/dictation/whisper-server.ts`), зупиняється з
     застосунком; усе, що заважає серверу, падає на `whisper-cli` — повільніше, але не зламано.
     **Жоден запит не чекає на старт сервера:** поки він піднімається, фразу бере
     `whisper-cli`. Перший старт після інсталу — **13 с** (Gatekeeper перевіряє свіжопідписаний
     бінарник, заміряно), далі ~1 с; блокувати на цьому диктовку означало б зробити її
     повільнішою, ніж до #218. `MARSHAL_WHISPER_SERVER=0` — вимкнути. `setup:dictation` збирає
     обидва бінарники; підписує їх electron-builder разом з рештою бандла.
  2. **macOS permissions для `npm run desktop` (dev mode):**
     - `npm run build` автоматично патчить `node_modules/electron/dist/Electron.app/Contents/Info.plist` (додає `NSMicrophoneUsageDescription` + `NSScreenCaptureUsageDescription` + `CFBundleIdentifier=com.marshal.desktop.dev`), підписує bundle stable identity `Marshal Self-Signed` (якщо cert встановлений) і підписує всі Swift helpers (`audio-recorder`, `screen-recorder`, `scroll-capture`, `scroll-stitch`, `apple-vision-ocr`, `send-keystroke`) тією ж identity. Скрипти: `scripts/patch-electron-info-plist.sh` + `scripts/postbuild.mjs`.
     - При першому запуску системний prompt → **Allow** для Microphone (а також Accessibility для push-to-talk hotkey, якщо ще не ввімкнено).
     - Packaged build отримує ті ж keys через `package.json > build.mac.extendInfo` + stable identity `099164E16AE88B2052B842BE1036FB10411B7239`.
  3. **Жести правого ⌘ (`desktop/dictation/hotkey-manager.ts`, `GesturePushToTalkHotkey`):**
     утримання довше `holdDelayMs` (200) — **розмова з Marshal** (#361, нижче); два короткі натискання з паузою до
     `toggleTapThresholdMs` (350) — тумблер запису дзвінка, лише аудіо (#242; тільки поки
     `dictationToggleTapCount = 0`, інакше тапи належать hands-free диктовці). Якщо під час
     утримання натиснуто інший модифікатор чи клавішу, це шорткат, а не команда:
     `ptt-monitor` шле `cancel`, запис викидається без транскрипції й вставки (#239).
     Глобального `⌘⌥M` для диктовки більше немає (#240): він стояв поруч із `⌘⌥⇧M`, і
     замість запису дзвінка вмикалась диктовка, яка потім вставляла текст.
     **Доставка тексту — `⌘V`, не друкування** (`deliverTranscript`, #244): транскрипт уже в
     буфері, а одна подія вставки не може дійти наполовину. Друкування шматками (`insert-text`)
     rich-редактори (Claude, Slack) частково губили. Друкування лишається для застосунків без
     текстового поля (`NON_TEXT_FRONTMOST_APPS`) і як запасний шлях, коли `⌘V` не спрацював.
     **Утримання правого ⌘ — команда голосовому асистенту** (#361), як мікрофон у dock home:
     транскрипт іде в `AssistantDispatcher.submit`, перша така команда вмикає асистента
     (`enableAssistantOnce`). Диспетчер сам вирішує: сесія за іменем, сесія, що чекає, контекст,
     фіча Marshal або `./marshal insert "<текст>"` — текст надрукується в застосунку, що був
     frontmost **у момент натискання** (`DictationService.talkTarget`, знімається на key-down:
     поки диспетчер думає секунди, фокус уже деінде). `insert` повертає той застосунок
     (`open -a`), а далі — та сама доставка `⌘V`, що в диктовки.
     **Утримання правого ⌥ — звичайна диктовка у frontmost-застосунок** (~1 с, без диспетчера:
     через нього було б кілька секунд). Тапи на правому ⌥ нічого не значать
     (`toggleTapCount: 0`). `MARSHAL_PASTE_DICTATION_HOTKEY` — інша клавіша або `off`;
     `MARSHAL_DICTATION_HOTKEY` (Settings → «Talk to Marshal hotkey») — клавіша розмови.
     Колишня диктовка правим ⌥ у сесію Claude Code (#264, `session-router.ts`) прибрана: ту
     саму маршрутизацію (ім'я, сесія, що чекає, контекст) тепер робить диспетчер.
  4. **Промпт диктовки — бюджет у токенах, не в символах** (#289, #261). Whisper (і whisper.cpp,
     і Groq) бере лише **останні 223 токени** промпту й мовчки відрізає **початок**. Кирилиця
     коштує ~2 символи на токен, тож старий дефолт на 841 символ (288 токенів) щоразу губив
     директиву «дослівно, із суржиком», що стояла першою. Тепер порядок — від менш важливого до
     більш важливого: словник → директива → терміни з glossary перекладача (новіші — останні).
     `buildDictationPrompt` (`desktop/dictation/whisper-backend.ts`) обрізає зібраний промпт **з
     початку** до 210 токенів за консервативною оцінкою (`estimateWhisperTokens`, звірена з
     реальним токенізатором у `tests/dictation-prompt.test.ts`); glossary бере не більше 90.
     Порожній промпт у Settings = жодного промпту, і glossary теж. `settings.json` зберігає
     **текст** дефолту, тож старі дефолти (`PREVIOUS_DEFAULT_DICTATION_PROMPTS`) при завантаженні
     замінюються новим — міняєш дефолт, додай попередній у цей список.
     **Галюцинації не вставляються:** «Дякую за перегляд.», «Субтитри зроблені…», «Thank you.» на
     майже тихому натисканні відкидаються (`transcriptToDeliver` → `isLikelyHallucination`, спільний
     із субтитрами) — краще не вставити нічого.
  5. Debug: `MARSHAL_DICTATION_DEBUG=1 npm run desktop` — поаналізувати keydown/keyup/recorder state (див. #49, #50)
- Translator: налаштувати `MARSHAL_API_KEY` у `.env` (див. `.env.example`).
  **Для встановленого застосунку — `npm run setup:env`**: packaged білд шукає `.env` у своїй
  userData-теці, бо той, що в репо, лежить усередині `.app`. Тека зветься за top-level
  `productName` з package.json — `~/Library/Application Support/Marshal/` (з #158; до того була
  `local-chatgpt-agent/`, і перший запуск нової збірки один раз копіює її вміст, стару теку не
  чіпає). Шлях не хардкодити: скрипт виводить його сам, а Settings → Setup health друкує те, що
  реально зарезолвив запущений застосунок.
  Ключ потрібен лише для `codex-cli`-бриджу: без нього `auto` лишається на codex і переклад
  займає ~10 с (#155). Бридж `claude-cli` (дефолт) перекладає через Claude CLI за ~1–2 с (#344).
  Стан агента (проєкти й сесії в `operator-data/`, профілі й auth браузерних бриджів у
  `agent/.chrome-profile`, `agent/.claude-web-profile`, `agent/.auth/`) у packaged білді живе в
  `<userData>/`, у dev — як і раніше в корені репо. Корінь — `MARSHAL_DATA_DIR`, його ставить
  main; шляхи рахуються тільки через `resolveDataPath` (`agent/config/data-path.ts`), не від
  `process.cwd()`: застосунок, запущений з Finder/Dock, отримує `cwd = /`, і backend не
  піднімався взагалі (#206, #233). Відносні шляхи з `.env` лягають у той самий корінь.
  Override лише для сесій — `MARSHAL_OPERATOR_DATA_DIR`.
- **Marshal — LSUIElement застосунок: немає іконки в Dock і рядка в ⌘Tab.** Наслідок, який
  ламає вікна: звичайне вікно, що опинилось за іншим, **неможливо підняти жодним системним
  способом**. Тому перекладач, закріплений скріншот і редактор захоплення тримаються
  `alwaysOnTop`, а не тому, що «так гарніше» (#168). Додаєш нове вікно — або роби його
  floating, або дай шлях назад через tray; `BrowserWindow.focus()` сам по собі для
  LSUIElement не спрацьовує, потрібен `app.focus({ steal: true })`.
  `setVisibleOnAllWorkspaces(…)` — **будь-який виклик лише з `skipTransformProcessType: true`**:
  без нього Electron робить `DockShow`/`DockHide`, і `false` перетворює Marshal на Foreground-app
  (`lsappinfo` → `type="Foreground"`). Тоді будь-яке вікно чи індикатор активує застосунок,
  Marshal стає frontmost без жодного вікна, і диктовка «вставляє» текст у нікуди (#243).
- **Вікно перекладача не ховається, поки в полі є текст** (#166). `blur` прилітає від
  нотифікацій і застосунків, що стартують, — це не рішення викинути набране. Порожнє вікно
  ховається як і раніше. Правила живуть у `desktop/translator/window-policy.ts` окремо від
  Electron саме щоб бути тестованими; renderer повідомляє лише переходи порожнє↔непорожнє.
  `⌘⌥T` тепер тумблер, а не «завжди перекласти буфер»: на порожньому буфері він раніше не
  робив **нічого**, і єдиним шляхом назад було головне вікно.
- **Подвійний ⌘C, `⌘⌥T` і `⌘⇧2` відкривають compact popup, як у DeepL** (#344): 420 px завширшки,
  лише переклад, Insert і Copy; висоту під вміст рахує renderer (`reportCompactHeight` →
  `marshal:translator-fit`), main затискає її в 96–440 px. Кнопка Expand
  (`marshal:translator-expand`) розгортає popup у повне вікно, лівий верхній кут лишається на
  місці. Popup ховається на будь-якому `blur`, навіть із текстом (`shouldHideOnBlur`, `compact`):
  він показує результат, а не чернетку. Результат у себе отримує лише повне вікно, яке зараз на
  екрані. Сам `pinned` цього не робить: він зберігається, і закрите pinned-вікно забирало б кожен
  popup (#348). Результат OCR приходить разом із розпізнаним текстом (`sourceText`). Він стоїть у лівій
  панелі, тож після Expand його видно і правка перекладає заново. OCR знімає дисплей під курсором,
  а не primary. Перевірка — `npm run test:e2e:alternatives`, там є compact-кроки;
  `MARSHAL_E2E_SHOTS=<тека>` зберігає знімок popup-а.
- **Glossary перекладача — не декорація, а виконання правила «технічні терміни не
  перекладати».** Іконка книги у вікні перекладача. Термін без перекладу = лишити як є
  (`backoff`, `rate limit`, `product_flat`); з перекладом = саме так і рендерити
  (`cache tag` → `тег кешу`). Сховище — `translator-glossary.json` в userData. У промпт
  ідуть **лише терміни, що є в тексті** (`selectGlossaryEntries`) — інакше довгий список
  роздуває кожен запит і розмиває інструкцію. Матчинг на межі слова через `\p{L}`
  lookaround, не `\b`: `\b` ASCII-only і кириличні терміни промахує (#147).
- **Альтернативні переклади — клік по слову в правій панелі** (#146). Переклад рендериться
  не одним текстовим вузлом, а словами-спанами (`desktop/renderer/translator-alternatives.js`:
  токенізація, межі речення, застосування вибору — чисті функції, тестовані без Electron).
  Запит іде **на речення, не на весь текст**, і кожна альтернатива повертається разом із
  **повністю переписаним реченням**: DeepL після вибору переписує хвіст другим запитом, а тут
  один запит дає і список, і готовий результат, тому вибір застосовується миттєво. Кеш —
  по `(мова, речення, слово, зсув)`, тож повторний клік безкоштовний. Контракт промпту й
  парсер — `desktop/translator/backends/alternatives.ts`; метод `suggestAlternatives`
  **опціональний** у `TranslatorBackend`, бо Apple Vision — OCR-only, і сервіс перетворює
  його відсутність на повідомлення з назвою провайдера, а не на краш. Перевірка UI —
  `npm run test:e2e:alternatives` (реальний renderer у Electron зі stub-preload, без ключа
  й без мережі).
- **Модель перекладача — `MARSHAL_TRANSLATOR_MODEL`, не `MARSHAL_MODEL`.** Друга спільна з
  агентськими бриджами. Дефолт — `qwen/qwen3.8-27b` (заміряно 127–559 мс на речення проти
  556–1631 мс у gpt-oss, ідентифікатори й переноси зберігає). Набір моделей у Groq **змінюється**:
  `llama-3.3-70b-versatile` зник і 404-ив кожен переклад (#162). Що є на акаунті —
  `GET /v1/models`, не вгадувати. 404 `model_not_found` тепер падає на CLI, як і 401 (#160).
- **Claude CLI backend перекладача — підписка, не ключ** (#344,
  `desktop/translator/backends/claude-cli-backend.ts`). Модель береться з
  `MARSHAL_TRANSLATOR_CLAUDE_MODEL` (дефолт `haiku`), **не** з `MARSHAL_CLAUDE_MODEL`. Друга змінна
  належить агенту (зазвичай opus), і з нею кожен переклад тривав 11–16 с. Один запит обслуговує один
  `claude -p` зі stream-json на вході: процес стартує раніше, ніж з'являється запит. Звичайний `-p` за
  3 с порожнього stdin здається. Один процес завжди тримається запасним. Його прогрівають
  відкриття перекладача і старт `⌘⇧2`. Без запитів він живе 10 хв: це ~117 МБ, а idle-бюджет

  tmp-файлу й Read tool. Модель одним запитом читає текст і перекладає його

  1568 px по довшій стороні, а формати, яких Claude не читає, перетворює на PNG

  розірвані версткою рядки склеює `unwrapOcrLines`. Помилки «перекладу з картинки» насправді
  давав Groq-переклад рядків, а не OCR.

- **Запис дзвінків (Meet / Zoom / Slack) — `desktop/meeting/`** (#229). Tray → «Record Meeting

  ротації наступний чанк стартує **до** мікшування попереднього, а фінальний файл збирається
  по wall-clock (`adelay` + `amix normalize=0`), а не `concat`: зазори між чанками лишаються

  хендл: helper попереднього чанку отримує `quit` і виходить уже **після** того, як
  наступний заспавнений, і його `exit` обнуляв посилання на живий. Стоп не доходив,
  AVAssetWriter не дописував `moov`, і system-аудіо кожного чанку після першого було
  нечитабельним. Тому ж: чанк, чий system-трек не читається, мікшується **лише з
  мікрофоном** (з попередженням), а не валить увесь запис; збій ротації (вона йде з
  таймера) і смерть helper-а посеред дзвінка — подія `warning` → нотифікація **одразу**,
  а не мовчки до зупинки; сирі файли чанку, що не потрапив у фінал, не видаляються (#251).

  перемальовує його на ній. `data-i18n` замінює весь вміст елемента — не вішати його на елемент
  з дочірніми `id`/обробниками чи текстом, який переписує JS. Новий рядок = ключ в обох каталогах;
  `tests/i18n-catalog.test.ts` стереже однакові ключі, плейсхолдери й теги та те, що кожен ключ із
  розмітки й `t("…")` у renderer існує. Технічні терміни українською не перекладаються (hooks,
  worktree, rate limit, backend, summary, OCR); назви розділів System Settings лишаються англійською.
  Англійською лишаються й діагностика (сирі помилки backend-ів, бібліотек і permission-перевірок,
  попередження записувача в `manifest`) та вміст, який генерує модель (нотатки, summary, переклад).
  e2e зі stub-preload без мови отримують `en`; home і віджет беруть мову ще й з payload стану.
- **Встановлення свіжого білду на свою машину — `npm run install:local`** (не тягнути DMG
  руками). Білди self-signed і не нотаризовані, тому macOS вішає `com.apple.quarantine` і
  блокує перший запуск. Скрипт гасить запущений Marshal, копіює з образу в `/Applications`,
  знімає атрибут і перевіряє підпис — діалогу немає взагалі (#153). Нотаризація прибрала б
  його і для сторонніх, але потребує `Developer ID Application`, тобто платного Apple
  Developer Program — поки не купуємо.
  **Що саме встановлено — Settings → Setup health → Build** (#228): версія, git-ревізія,
  гілка, «+ uncommitted changes» і час збирання. `CFBundleVersion` між dev-білдами не
  змінюється, тож «це вже той білд з фіксом?» інакше не з'ясувати. Пише це
  `scripts/postbuild.mjs` у `dist/desktop/build-info.json`.

## Стек проєкту

## Архітектура на високому рівні
- `desktop/main.ts` — Electron main process, IPC hub, global shortcuts
- `desktop/backend-client.ts` — UtilityProcess клієнт до agent backend
- `desktop/translator/` — floating translator: two-pane window, 42-language registry
  (`languages.ts` — single source of truth, renderer gets it over IPC), translate-as-you-type,
  insert-into-app (`insert-service.ts`), 5 backends under `backends/`, Swift pasteboard watcher
- `desktop/claude-code/` — інтеграція з Claude Code. `registry.ts` читає
  `~/.claude/sessions/<pid>.json`, які пише сам Claude Code (формат **недокументований**,
  знятий з реальних файлів 2.1.317): `kind` (`interactive` / `bg` / `daemon` / `daemon-worker`),
  `status` (`busy` / `shell` / `idle` / `waiting`) і `waitingFor` («permission prompt», «input
  needed»…) уже лежать у файлі. Live = `kind: "interactive"` + pid живий + сокет існує; файл,
  що не збігся з форматом, пропускається з одним рядком у лог. Читається **лише на вимогу**
  (tray → «Claude Sessions» будує список у момент відкриття меню), без watcher-а (#281).
  `focus.ts`: клік по сесії — вкладка Terminal/iTerm за tty через AppleScript, desktop-сесія
  (tty немає) — `claude://code/continue?session=<hostSessionId>` (#357), інакше `open -a`
  застосунку-хоста з дерева процесів.
  **Hooks (#263)** — Settings → «Claude Code integration» → Install/Remove: лише явна дія
  користувача. `hook-installer.ts` **мерджить** `Stop` і `Notification` (`async: true`) у
  `~/.claude/settings.json` поруч із чужими hooks; свої записи впізнає за `marshal-claude-hook.sh`
  у команді, uninstall прибирає лише їх (файл, що не парситься, не чіпає; symlink і відступ
  зберігає). Скрипт (`<userData>/claude-code/marshal-claude-hook.sh`, sh + curl, без Node) шле
  payload на `127.0.0.1:<port>/claude-code/hook` з per-run токеном (`port` і `auth-header` у тій
  самій теці, 0600); сервер (`hook-service.ts`) відкидає будь-який `Origin` і чужий `Host` — веб-
  сторінка подію не підкине. Marshal не запущений → подія лягає в `spool/`, на старті
  програється; дедуп — session id + хеш payload (не uuid транскрипту: до replay він уже інший),
  старші 15 хв — викидаються. Сервер живе лише поки hooks встановлені, таймерів немає;
  нагадування «still waiting» через 10 хв — один `setTimeout` на сесію, що чекає, і перевірка
  статусу в registry (відповідь у терміналі hook-а не дає). Summary «finished» — один
  не-стрімовий запит через провайдера captions (`resolveSummaryProvider`), мова — setting
  `claudeCodeSummaryLanguage` (auto = мова відповіді); коротку однорядкову відповідь показує
  як є, без запиту. `idle_prompt` ігнорується — він повторює вже показаний Stop.
  **Dossiers сесій (#286)** — з них диспетчер голосового асистента (#318) вирішує, якій сесії
  передати команду без імені: `./marshal context` → `ClaudeHooksController.routingContext` віддає
  JSON (name, folder, dossier) або `off`, коли вимкнено setting `claudeCodeContextRouting` чи жодна
  жива сесія не в дозволених теках. Колишні диктовка правим ⌥ у сесію (#264, picker) і власний
  роутер-модель (`ContextRouter.route`, «Sent to … by context») прибрані в #361 і #364: вибір робить
  диспетчер. Dossier (`dossier.ts`) — 3 рядки англійською (Project / Feature / Now), будує мала
  модель з хвоста transcript-а; перебудова лише коли transcript змінився **і** минуло ≥ 10 хв,
  тригери — Stop hook і сам `./marshal context`, таймера немає (#281). Зберігаються в
  `<userData>/claude-code/dossiers.json`, старші доби викидаються. Transcript —
  `~/.claude/projects/<encoded cwd>/<sessionId>.jsonl` (формат недокументований, знятий з
  2.1.317): кодування теки між версіями різне (`_` то лишається, то ні), тому спершу здогад, потім
  скан за `<sessionId>.jsonl`. Читається останній 1 МБ: `user`/`assistant` без `isSidechain` і
  `isMeta`, лише `text`-блоки, `<system-reminder>` вирізається. Провайдер — той самий, що в summary
  «finished» (`completeOnce` в `answer-summary.ts` поверх `resolveSummaryProvider`), окремого SDK
  немає.
  **Читаються лише сесії з дозволених тек** (#303, `parseRoutingRoots` / `isUnderRoots` у
  `context-router.ts`): Settings → «Folders whose sessions may be read» (`claudeCodeRoutingRoots`,
  тека на рядок, `~/` = home). Один Claude Code на машині тримає сесії різних роботодавців, і
  transcript робочої сесії не має йти через особистий ключ. **Порожньо = не читається жодна**
  (`./marshal context` → `off`). Сесія поза теками не отримує dossier і не потрапляє в context,
  але диспетчер бачить її в `./marshal sessions` і передає їй команду за іменем.
  Скільки живих сесій читається зараз — рядок під полем.
- `desktop/renderer/` — UI (vanilla JS, без фреймворку)
- `agent/bridge/` — 7 reasoning bridges (claude-cli — default, codex-cli, api, claude, claude-web, playwright, extension)
- `agent/runtime/marshal.ts` — один-shot executor, Toolbox (shell, fs, browser)
- `chrome-extension/` — side panel для ChatGPT/Claude/Gemini + local HTTP bridge
